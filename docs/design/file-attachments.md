# 文件附件

上传的文本、PDF、Office 和压缩包保留原文件，不再把整份提取文本拼进模型输入。图片和音频继续使用各自的输入通道。

## 生命周期

1. 渲染层通过 `attachment:stage` 将字节交给主进程。原文件保存到数据目录下 `attachments/documents/<UUID>/original`，同时记录名称、大小和 SHA-256。上传状态和错误属于会话草稿，切页不丢失。
2. 上传得到的随机 claim token 只用于发送时首次绑定会话，不进入聊天正文、模型输入或工具结果。尚未发送的上传不能被工具读取。每条消息最多 32 个文件，单个文件最多 25 MiB。
3. 发送正文保留文件说明和 `[attachment:UUID]` 引用；界面隐藏引用 ID。模型通过只读 `read_attachment` 获取关联文件列表、结构索引和内容。
4. 恢复会话沿用磁盘记录；分叉共享原文件并复制关联。子 Agent 只能继承真实父链的附件。删除会话移除关联，当前实现保留原文件，不自动回收未发送或失去关联的文件。

旧版本已经内联的文本保持可读，但当时被丢弃的原文件无法补回，需要重新上传。

## 按需读取

`read_attachment` 不传 `attachmentId` 时列出本会话文件。`mode=index` 返回 PDF 页、Word 文档部分、Excel 工作表、PowerPoint 幻灯片或压缩包成员，索引默认 50 项、最多 100 项。压缩包中的文档可传 `member` 继续索引。

`mode=read` 读取 `section`（从 1 开始，默认 1），压缩包同时指定精确 `member`。内容默认最多 16 KiB、单次最多 32 KiB，`offset` 是 UTF-8 字节偏移。截断结果返回 `nextOffset`，模型应继续读取，不能把预览当成全文。文本文件同样可分段读取，旧的 128 KiB 内联上限不再丢弃上传内容。

按需指返回的逻辑范围，并不保证所有格式都支持随机访问底层压缩流：Office/压缩包仍需展开并建立结构，部分旧 Office 解析器需要扫描整个文件。解析在限时的独立进程串行执行，最多容纳 4 个进行中或等待中的读取。结果按附件、解析器缓存版本和查询参数持久缓存；每次读取仍核对原文件哈希。

## 解析边界

- PDF 使用匹配的 PDF.js Node 读取器、worker、CMaps 和标准字体文件，不依赖网络加载字体。扫描页明确要求 OCR，目前不执行 OCR。
- Excel 保留格式化日期、百分比、布尔值和公式；缓存结果与缺失缓存明确区分，不执行公式或宏。
- Word 保留段落、制表符、换行和表格边界。PPT/PPTX 保留演讲备注。OOXML 关系通过命名空间 URI 解析，支持不同前缀。
- 压缩包只在 WASM 内存文件系统展开。拒绝加密包、路径穿越、链接、超过 512 项或累计展开超过 64 MiB 的内容。嵌套文档按成员读取；嵌套压缩包不递归展开。TAR.GZ/TGZ 的外层封装除外。
- 文件内容始终视为不可信数据。工具不执行附件中的指令、宏或程序；不支持的成员和损坏文件明确报错，原文件仍保留。

## 回归验证

`test-document-attachments.ts` 覆盖真实旧 Office/RAR 样本、格式/换行/备注/关系前缀、中文 PDF、按需范围和压缩包限制，并在仅有打包依赖的临时目录运行解析 worker。`test-attachment-store.ts` 覆盖原字节、会话关联、缓存、恢复/分叉、越权及文件替换。Go 测试验证只读工具、可信会话 ID 和宿主桥接；Electron `smoke-work.cjs` 验证真实 Vue、preload、IPC、后台解析和切页期间的上传状态。
