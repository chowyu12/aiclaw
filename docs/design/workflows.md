# 持久任务、恢复、分叉与文件改动

2026-10-03。内核、agent-client 和桌面端共用这一套协议。功能入口位于聊天页顶部；
用户和助手消息旁的「从这里分叉」按那条消息的位置复制历史。

## 生成图片预览

生成工具的图片产物直接显示在该轮回答下方，单张显示预览，多张以缩略图排列。
点击图片在应用内查看大图，Esc 或关闭按钮返回；文件名仍可打开本地文件。
图片进入可见区域后才读取，加载失败只在对应图片旁提示，不遮住回答。
产物路径随工具结果保存，重新打开会话后可恢复。旧记录兼容直接调用和 Code Mode
`exec` 输出的标准中英文生成结果（含 JSON 字符串），不从助手正文猜测文件路径。

## 目标与计划

目标包含 objective、acceptance、steps、status、evidence、tokenBudget、timeBudgetMs、
tokensUsed、elapsedMs。计划步骤为 pending / in_progress / completed，至多一步进行中。

用户可以在面板填写目标、验收条件、计划与预算，然后创建并开始；也可以明确要求模型
使用 create_goal。模型通过 get_goal / update_goal 读取和更新计划。结束必须有验证记录，
且所有步骤已完成；模型不能自行恢复目标或提高预算。完成判断仍由模型或用户根据证据
作出，系统校验字段及步骤状态，不把“有一段证据文字”当成外部事实验证。

状态为 active / paused / blocked / complete / budget_exhausted。用户可暂停（同时中断当前子代理树）、调整预算、
继续执行或补充验证记录。活动目标在模型给出普通回答后继续推进，越过普通对话的
40 次循环限制；连续三次回答没有计划进展时转为 blocked，等待用户处理。
普通对话保持原有循环上限。目标不跨应用关闭自动运行；内核重启将 active 目标转为
paused。恢复提示未处理时不允许恢复目标。用户发新消息仍可纠正方向。

时间预算为当前会话实际执行时间，包含等待模型、工具和审批的时间，排除暂停与关闭
应用的时间。计时器可取消正在等待的模型和支持取消的工具，并中断子代理树；已发出的外部操作不保证能
撤销。Token 统计使用上游返回的用量，包含当前会话的重试、压缩和视觉调用，不汇总
独立子会话或外部服务的费用。一次已经发出的请求可能超过剩余预算，收到用量后停止
后续调用。上游缺少用量时标记累计值不完整；有 Token 预算的目标暂停，不能带着不可
核实的余额继续执行，用户可检查后移除 Token 预算或新建目标。进程突然终止时，尚未
返回的调用用量无法补算；因此恢复需要人工检查，而不是承诺跨崩溃精确计费。

## 请求与执行恢复

SQLite 新增 submissions、transcript、work_state 表，外键跟随会话删除。

- 接收 turn/start 时，先持久化 requestId、载荷指纹、输入附件及回执，再排队或调度。
  重复 ID 加相同载荷返回原轮次；不同载荷报错。去重跨内核重启生效。
- queued 表示尚未消费；running 表示已经开始处理。运行中插话先更新所属轮次回执再入队，
  以免回执指向一个不存在的轮次。当前执行也单独记录，覆盖子会话等不经桌面发送的入口。
- 内核启动把 running 标记为 uncertain，不自动重放。已完成请求保留回执用于去重。
  正常完成的消息、工具调用意图和工具结果写入 transcript，模型调用与工具批次之前保存
  上下文检查点；流式响应中尚未完成的文本不保证在硬崩溃后保留。
- 聊天面板列出 queued 与 uncertain。用户可处理尚未消费的输入，或检查后移除提示。
  uncertain 只提供检查/移除入口；后续动作需发送新指令。移除提示或恢复输入时也清理
  内存队列，防止同一输入被再次消费。
- 恢复时用已记录的工具结果重建上下文，为缺失的结果补上“可能已经执行，请先检查状态”
  标记。SQLite 和外部副作用没有共同事务，因此不承诺恰好执行一次。

图片及文本保存在接收记录中；音频沿用宿主已保存的附件路径。恢复时文件仍须存在。
模型等待失败、取消及预算终止也可能留下待检查记录，避免把不完整执行误当成成功。

## 恢复一致性与轮次权限（2026-10-08）

对照 Codex 0.161 的 [恢复历史修复](https://github.com/openai/codex/pull/49599)
和 [轮次授权归属](https://github.com/openai/codex/pull/49880)：恢复会话先读取配置以挂载工具，
挂载完成后重新读取已提交的历史、标题和轮次计数，避免耗时的 MCP 初始化期间提交的结果
被旧快照覆盖。桌面输入提交与重挂前的检查/保存/卸载互斥；已提交但尚未进入 RunTurn 的
轮次同样阻止重挂。重挂前保存失败直接报错并保留原会话。慢速挂载不持有输入提交锁，
其他会话仍可接受输入。这是单内核进程的协调，不提供多进程共同写库的所有权协议。

工具执行环境在会话锁内取得工作目录、审批策略、沙箱开关和敏感路径副本；代码模式的
嵌套调用沿用该轮环境、审批通道及 turn ID。新配置不修改旧环境。只有用户明确批准的
会话目录授权继续通过原有 Grants/Grant 在本会话各轮间共享。当前代码模式等待工具完成
后才返回，同一会话轮次串行执行，未引入跨轮后台脚本或新的临时授权作用域。

## 数据库损坏检测与保留（2026-10-08）

应用库和会话库在建表/迁移前执行 `PRAGMA quick_check(1)`，扫描上下文预算 250 ms，
检查期间的 SQLite 锁等待最多 100 ms，之后恢复连接原设置。超时、锁定或中断只记为
检查未完成，不认定数据库损坏；正常初始化若失败仍向用户报错。

确认损坏时关闭连接，将主文件及存在的 `-wal`、`-shm`、`-journal` 复制到
`<数据库路径>.recovery/corrupt-*/`，目录权限 0700、备份文件 0600，原库保留。
启动失败信息包含备份位置；复制失败也明确报错，不假称备份成功。应用库备份目录进入
敏感路径保护，模型不可读取。关闭应用后应从已知有效备份恢复，并保留损坏副本用于
人工检查；损坏副本不等于可用备份，也不保证其他进程仍在写库时的文件一致性。

两库都保存无法完整重建的用户数据，因此本次不自动重建或替换。这与 Codex
[按恢复能力区分数据库](https://github.com/openai/codex/pull/49701) 的原则一致。

回归覆盖：`agent/resume_test.go`（挂载期间的新提交）、`server/resume_test.go`
（保存失败及已提交未开跑）、`agent/permissions_test.go`（代码模式审批归属与权限快照）、
`internal/sqlitehealth/check_test.go`（页面损坏、锁定、取消、原件与伴随文件保留），以及
`store/corruption_test.go`、`appdb/corruption_test.go`（真实启动入口）。

## 普通会话分叉

session/fork 接受 sessionId、可选 itemId 和可选 model。省略 itemId 复制全部已保存的
历史，指定时复制到那条消息；工具调用边界只复制结果齐全的部分。分叉按不可变 transcript
取历史，后续上下文压缩不会删除已经归档的原始消息。旧版本从未保存的压缩前历史无法
补回。

新会话保留来源 sessionId / itemId，使用当前系统提示词和工具配置；它是普通会话，
不挂到子代理树，不继承源会话的目标、待执行队列、文件撤销记录或临时权限授权。
模型默认沿用，也可通过协议指定或在新会话的模型选择器中切换。

分叉复制对话，不复制文件或创建 Git worktree；两边继续共用原工作目录。源会话执行中
禁止分叉，以免选中尚不完整的历史。来源链接可回到原会话。

## 文件改动查看与撤销

write_file、edit_file 在写入前保存原文、目标内容、文件是否存在及权限，再进行写入。
记录存于会话数据库，可跨重启查看。聊天面板列出文件和文本差异、已撤销状态与冲突。

撤销按单次改动进行：磁盘内容必须仍与该次写入结果一致，路径须仍是原来的普通文件，
并通过当前敏感路径检查。文件被外部修改、替换成符号链接或路径重定向时拒绝覆盖。
修改原文件会恢复原文；新建文件会被删除。多次改动同一文件时按从后往前撤销。
撤销也先记录意图；中途崩溃后可确认已经恢复的内容并收尾，不再次覆盖文件。

此版范围为 UTF-8 文本文件（每份最多 4 MiB），差异最多展示 3000 行，校验用完整内容。
不包含 run_command、MCP、Office 或其他外部工具的文件改动；这些工具没有共享写入入口，
不能据此声称整个工作区可回滚。进程内文件操作串行化，外部编辑器不参与此锁；冲突检查
可以保护已观察到的改动，不提供与外部进程之间的原子比较交换保证。

## MCP OAuth 登录

设置 → MCP 的远程 HTTP server 可启用 OAuth，点击登录在系统浏览器授权。支持自动客户端
注册，也可填写预注册 Client ID、可选 Client Secret、Scope 和固定回调端口。固定端口的回调
地址是 `http://127.0.0.1:端口/oauth/callback`；自动端口适用于支持动态注册的服务。

内核根据 protected-resource metadata 发现授权服务器，校验资源与 issuer，采用授权码、
PKCE S256 和一次性 state。回调仅监听本机；错误 state 不消费授权，授权窗口五分钟过期。
外部授权与 token 端点要求 HTTPS，本机测试端点允许 HTTP；凭据请求不跟随重定向。
实现依据 [MCP HTTP 授权规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization)。

access/refresh token 及 client secret 复用现有 AES-256-GCM 主密钥，存于应用库旁的
`mcp-oauth.enc`，权限 0600，原子替换。配置 JSON、会话历史和 renderer 只保存授权开关、
非秘密客户端配置及状态。模型不可读凭据文件；清空数据同时移除它。

每次 MCP HTTP 请求动态取 token，过期前刷新；并发刷新串行化，轮换 refresh token 持久化。
登出取消待授权回调并删除本地凭据，已挂载连接的后续请求也无法使用旧 token。此处登出是
本地退出，不宣称撤销服务端授予的权限。HTTP 401 的工具调用不会自动重放；用户可重新登录。

仅支持提供 protected-resource 与授权服务器 metadata、PKCE S256 的现代 OAuth 服务。
不支持旧 HTTP+SSE 传输，不自动兼容缺少这些元数据的私有鉴权服务。

## 原会话持续跟进

设置 → 定时任务选择「在原会话跟进」，指定会话、指令、排期及可选停止条件。对话中的
`schedule_create` 默认绑定当前会话；`mode: cron` 保留每次新建会话的行为，旧任务继续使用
原方式。跟进保留源会话的模型与历史，工具配置按现有恢复规则刷新，不更改侧边栏分组。

宿主将上次结果与停止条件交给模型；模型通过 `schedule_report` 返回 result、稳定的
result_key、complete。key 应描述观察到的状态，不含检查时间或变化的措辞。首次结果、key
变化、失败或满足停止条件才通知；也可选择每次通知。正常但无变化的检查仍留在原会话历史。

每轮拥有独立 run ID 和 turn ID，报告校验任务、run 和原会话；别的用户轮次完成不能结束
这次检查。结果与 key 持久化到原子的 `schedules.json`，完成事件早于回执时暂存并对齐回执。
只有显式填写停止条件且成功报告 complete 才自动停用；条件的事实验证由模型执行，宿主
校验报告归属与字段，不把模型声明当成独立事实证明。

原会话忙碌、有未完成目标、存在恢复提示、已归档或已删除时拒绝自动插话。并发手动点击
不会重复派发，同一原会话不能同时跑多个跟进。缺失报告、执行失败或应用重启发现上次仍
运行时，跟进暂停并要求检查，不自动重放结果不确定的任务。任务仍只在应用打开时运行，
原有最短五分钟间隔与十二小时以内补跑规则保留，关闭应用期间没有后台守护进程。

## 会话重命名

侧边栏会话行的编辑按钮、搜索结果和已归档列表支持重命名。编辑框回车保存，
Esc 或取消放弃，失败时保留输入并显示错误；保存期间防止重复提交。
`session/rename` 接收 sessionId 和 title，前后空白会去掉，名称不能为空、至多
200 个 Unicode 字符，且不能包含换行或控制字符。

重命名只修改显示名称，不变更对话、工作目录、模型、执行状态、归档状态或列表排序。
已加载会话同步更新内存标题；未加载会话直接更新数据库，无需挂载模型或 MCP。
SQLite 自动为旧数据库添加 manual_title 列，保存检查点时保留该字段对应的手动名称，
避免旧快照、正在执行的轮次或重启后的自动标题覆盖它。

## 文件卡片与生成文件

回复中的行内文件路径和本地 Markdown 文件链接在原位置显示类型与文件名卡片，完整路径
保留在打开动作中，不显示目录。点击或键盘回车、空格使用现有主进程校验后的本地打开入口。
不改变远程链接、围栏代码块或复制回答时的 Markdown 原文。

write_file、write_docx、write_xlsx、write_pptx 成功写入后登记产物，包括通过 Code Mode 调用的输出。
产物元数据随工具结果持久化，重新打开会话后恢复。仅未在正文提及的文件留在末尾卡片区，
不显示汇总标题或数量；已经预览的图片不重复列为文件卡片。不同目录的同名文件保留区别，
无法明确匹配正文引用时不去重。旧记录里的正文文件引用也会渲染卡片，无元数据时不推断其他产物。

## 回答操作与反馈

用户消息下方沿气泡右侧对齐，依次显示时间、复制和分叉图标。
回答下方依次显示时间、复制、分叉、有帮助、没帮助。操作使用统一图标按钮，保留提示与
无障碍标签；赞踩互斥，再次点击同一反馈可取消。反馈按会话和轮次保存在本机渲染存储中，
重新打开会话后恢复；不发送给模型或外部服务。旧消息没有时间时不补造时间。

## 会话侧栏展示

侧栏按会话的工作区完整路径归类，工作区和组内会话按最近活跃时间排序。
同名目录显示父目录，悬停可查看完整路径；未设置工作区的会话显示在“普通会话”。
渠道和定时任务会话遵循同样的工作区归属，以来源标签区分；子 Agent 继续挂在父会话下。
搜索覆盖所有会话，结果显示所属工作区。更改当前会话工作区后刷新侧栏归属。

自定义分组的切换、新建和移动入口已移除，原分组数据保留。
工作区仅是展示分类，不会改变目录或会话数据；折叠状态沿用现有宿主存储，
以完整路径作为独立键保存。

工作区标题使用文件夹图标，会话列表缩进显示标题，时间、轮次和模型信息放在悬停提示中。
选中行使用浅色背景，重命名、归档和删除按钮在悬停或键盘聚焦时显示；搜索结果保留命中片段。

工作区标题右侧在悬停或聚焦时显示更多操作和新建会话按钮。新会话继承该工作区完整路径，
并展开对应栏目。更多菜单支持置顶/取消置顶、在 Finder 中显示目录和批量归档会话。
置顶按完整路径保存在本机，重启后恢复；同名工作区分别处理。批量归档需确认会话数量，
包含子 Agent，沿用现有归档入口停止任务并支持恢复，不删除工作区文件。
