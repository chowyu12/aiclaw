# 浏览器工具：与 browser-use 的对照

对照对象：[browser-use/browser-use](https://github.com/browser-use/browser-use)，
一个 Python 库，让 LLM 驾驭 Chromium 完成网页任务。它的核心做法是把页面上可交互的
元素编号交给模型（DOM indexing），模型按编号点、填、选，辅以截图；带自己的浏览器
会话管理、云端浏览器与专用模型。

AIClaw 是桌面 Agent 应用，不是浏览器自动化库。对照的目的不是复刻它，而是把
「让模型可靠地上网办事」这件事上它已经验证过的做法拿进来，放在我们已有的
审批、沙箱、会话模型之下。

## 功能对照

| 能力 | browser-use | AIClaw（3.5 起） | 说明 |
|---|---|---|---|
| 页面表示：可交互元素编号列表 | ✅ DOM indexing | ✅ `browser_snapshot`：角色 + 文字 + 值 + 链接 + 视口内外 | 同一思路。我们的列表上限 150 个，超了让模型滚动 |
| 视觉：截图给模型看 | ✅ 可选 | ✅ `browser_screenshot`，按需 | 平时用编号列表，看布局 / 验证码时才截图 |
| 打开网址 | ✅ | ✅ `browser_navigate`，**要用户确认** | 出网且目标由模型决定，是唯一逐次确认的一步 |
| 点击 / 输入 / 下拉选择 / 滚动 / 按键 / 后退 | ✅ | ✅ 各一个工具 | 输入走真正的输入事件，React / Vue 受控输入能收到 |
| 抽正文 | ✅ `extract_content`（再交给 LLM 抽） | ✅ `browser_extract`（去导航脚本，给前 20K 字符） | 抽后的理解由对话模型自己做，不额外调一次模型 |
| 多标签 | ✅ | ⚠️ 自带窗口是单页；「用我的浏览器」下可列出并接管用户的标签页 | `browser_tabs` / `browser_use_tab` |
| 文件上传 | ✅ | ❌ | 需要宿主接文件选择器；下一版 |
| 拖拽 | ✅ | ❌ | 少见，暂不做 |
| 会话 / 登录态持久化 | ✅ profile、cookies 同步 | ✅ 独立持久分区 `persist:agent-browser`，登录态跨会话保留 | |
| 复用系统 Chrome 的登录 | ✅ `from_system_chrome()` | ✅「用我的浏览器」：经扩展在用户自己的 Chrome / Edge 里操作 | 见下文。不走远程调试口：Chrome 136 起默认配置不许开 |
| 有头 / 无头 | 都有 | 有头（窗口可见） | 让用户随时看见、随时接手；无头留待 CI 场景 |
| 域名白名单 | ✅ `allowed_domains` | ⚠️ 用审批代替：每次打开网址都问 | 白名单适合无人值守；我们无人值守（通道会话）根本不开浏览器 |
| 敏感数据占位（`sensitive_data`） | ✅ | ❌ | 让模型填「$password」由框架替换。有价值，下一版 |
| 自定义动作 / 工具 | ✅ `@tools.action` | ✅ 用 MCP server 或代码模式脚本组合 | 不同形态，同一目的 |
| 结构化输出 | ✅ Pydantic | ✅ 让对话模型按要求回 JSON；代码模式里脚本可直接 return 对象 | |
| 在脚本里批量操作 | ❌（Python 侧写循环） | ✅ 代码模式：`tools.browser_click()` 等在 exec 里可循环调用 | 翻十页搜索结果写成一段循环 |
| 云端浏览器 / 反检测 / 代理 | ✅ 收费 | ❌ | 不在这个应用的范围内 |
| 专用浏览器模型（BU 系列） | ✅ | ❌ | 用用户自己配的对话模型 |
| MCP server 形态对外提供 | ✅ | ❌ | 我们是消费 MCP 的一方 |
| 无需 Playwright / 浏览器驱动 | ❌ 需装 | ✅ Electron 自带 Chromium | 安装包不因此变大 |
| 审批 / 沙箱与其它工具一致 | 无此概念 | ✅ 打开网址走审批；严格档位逐步问；通道会话禁用 | 这是我们比它多的那一层 |

## 我们的选择

- **浏览器是宿主的，不是内核的。** Electron 里就带着 Chromium；接 Playwright 要多装
  一份浏览器、多一层版本对齐。内核只把工具调用翻译成 `browser/request`，与
  computer use 同一条路。
- **单独一个可见窗口，独立分区。** 与应用自己的渲染层完全隔开：网页拿不到 preload、
  拿不到 Node。登录态留在 `persist:agent-browser` 里，下次会话不用重新登。
- **只有打开网址要确认。** 一次点击可能是「下一页」也可能是「确认下单」，从元素上
  看不出区别，逐个问会把用户训练成闭眼点允许。严格档位下每一步都问，无人值守的
  通道会话根本没有这组工具。
- **页面内容是不可信的外部资料。** 编号列表与正文都包在边界标记里，与 AIHOT 这类
  外部信源同一个约定；工具描述里再说一次。这挡不住一个刻意伪装按钮的页面（browser-use
  也挡不住），挡得住的是「网页里一句冲着模型说的话被当成指令」。
- **收进代码模式。** 浏览器工具与内置工具、MCP 一起折进 `exec`，翻页、逐条点开这类
  重复动作写成脚本，中间结果不进上下文。

## 用我的浏览器（3.6 起）

设置 → 浏览器里可以选「我的浏览器（Chrome / Edge）」：浏览器工具不再开自带窗口，而是经
「AIClaw 浏览器助手」扩展（`apps/browser-extension`，MV3）在用户**自己的浏览器**里操作——
用他已有的登录，**在后台标签页里**，不抢鼠标，也不切换他正在看的页面。computer use 做不到
这一点：它截整屏、合成全局鼠标键盘，操作时用户没法用电脑。

- **为什么是扩展而不是远程调试口**：Chrome 136 起默认用户配置不能再开 `--remote-debugging-port`，
  接不上用户正在用的那个浏览器。扩展的 `chrome.debugger` 能对任意标签页发 CDP 命令，
  Claude in Chrome、Playwright MCP 的扩展模式都是这么做的。
- **扩展只是一层薄代理**：标签页管理（开后台标签页、归进「AIClaw」标签组、导航、后退）加 CDP 转发。
  快照、点击、输入这些动作的逻辑仍在主进程 `browser.ts` 里，与自带窗口共用一套（`PageDriver`
  的两个实现）；页面脚本经 `Runtime.evaluate` 执行，按键走 `Input.dispatchKeyEvent`，截图走
  `Page.captureScreenshot`（后台标签页也能截）。
- **默认只动自己开的标签页**：第一次 `browser_navigate` 在用户最近用的窗口里开一个不切过去的标签页。
  要操作用户已经打开的页面，模型先 `browser_tabs` 再 `browser_use_tab`，后者**每次都要确认**
  ——那是用户自己的页面、带着他的登录。
- **连接的安全**（`browser-bridge.ts`）：主进程只听 `127.0.0.1:17891`；握手前核对 Origin 必须是
  这个扩展（manifest 里固定了 key，ID 固定），网页伪造不了；之后双方用配对码做 HMAC 挑战-应答，
  **配对码本身不上线**。扩展同样核对 AIClaw 的证明：挡的是「AIClaw 没开时别的程序占住端口，
  冒充 AIClaw 驱动用户的浏览器」。配对码在设置页复制、重新生成后旧码立刻作废。
- **配对不用复制粘贴**（3.6.1 起）：没有配对码的扩展照样来连，AIClaw 回一个四位代码，扩展在浏览器里
  开配对页、设置页同时显示同一个代码；用户核对后**在浏览器里**点「允许」，AIClaw 才把配对码交过去，
  之后走的仍是不传码的挑战-应答。确认放在浏览器这边：没配对的扩展分不清对面是不是真的 AIClaw，
  AIClaw 没开时别的程序占住端口也能发起配对——只有让用户对着两边的代码点，才骗不到它。
  配对码失效（AIClaw 重新生成过）时扩展自动丢掉旧码、重新配对。手动粘贴配对码保留作备用。
- **安装引导**：选了「我的浏览器」而扩展没连上时，设置页列出本机的 Chrome / Edge / Brave / Arc，
  一键用它打开扩展管理页、在访达里显示扩展目录并把路径放进剪贴板（选择框里 Cmd+Shift+G 粘贴）。
  浏览器不允许应用悄悄装扩展，上架商店前最多做到这一步。
- **用户随时能停**：调试期间浏览器顶部有「正在调试」提示条，点「取消」扩展就断开，五分钟内
  不再自己接上那个标签页；空闲一分钟自动断开，提示条消失。
- **验证**：`scripts/test-browser-bridge.ts`（Origin、配对码、大消息、断开）、`scripts/test-browser-cdp.ts`；
  `make smoke-browser` 用临时配置的 Chrome / Edge 真装扩展、真跑 AgentBrowser：打开 → 快照 → 填字提交
  → 抽正文 → 截图 → 列标签页（核对是后台标签页）→ 后退。

## 已知差距（按价值排）

1. **文件上传**：需要宿主在 `file-chooser` 事件里接管，把模型给的路径（限工作区内）喂进去。
2. **敏感数据占位**：模型只看到 `$password`，宿主在输入时替换成真值，值不进对话历史。
3. **多标签**：给模型一份标签列表、切换与关闭。
4. **域名白名单**：配置一份允许的域名，命中的打开不再确认——给想少点确认的用户。
5. **无头模式**：给 `make scenarios` 这类自动化用。

## 验证

- Go：`internal/agent/browser_test.go`——只在开启时注册；打开网址要审批、页面内点击不问；
  严格档位逐步问；截图作为图片进下一次请求。
- 渲染 / 主进程纯函数：`scripts/test-browser-snapshot.ts`——编号列表的形状、不可信边界、
  截断说明、页面脚本不含出网能力。
- 桌面冒烟：`scripts/smoke-desktop.cjs` 里真开一个窗口，对一个内嵌页面做打开 → 快照 →
  填字 → 点击 → 抽正文，验的是 Electron 里这条路真通。
